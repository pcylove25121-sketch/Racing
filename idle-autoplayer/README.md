# 방치형 오토 (Idle Auto Player)

방치형 모바일 게임을 대신 플레이해 주는 안드로이드 앱이에요. 지정한 위치를 정해진 간격으로 탭·스와이프해 주는 **자동 터치(매크로)** 앱이고, 외부 라이브러리 없이 안드로이드 기본 API 만으로 만들었어요.

- **타겟 모드** : 번호 마커를 게임 버튼 위에 끌어다 놓으면 순서대로 눌러요.
- **녹화 모드** : 게임을 평소처럼 조작하면 탭·길게 누르기·스와이프와 사이 간격이 그대로 기록돼요.
- **반복 설정** : 반복 횟수(무한 가능), 바퀴 사이 대기, N분 후 자동 정지.
- **비상 정지** : 패널의 ■ 또는 **볼륨 아래 버튼**.
- 재생 중 화면이 꺼지지 않고, 화면 내용은 읽거나 전송하지 않아요.

> ⚠ iOS 는 앱이 다른 앱을 조작하는 것을 허용하지 않아서 안드로이드 전용이에요.
> ⚠ 게임마다 매크로를 약관으로 금지하고 제재하는 경우가 있어요. 운영 정책을 확인한 뒤 본인 책임으로 써 주세요.

## 설치 (APK 받기)

이 저장소에 푸시하면 GitHub Actions 가 자동으로 APK 를 빌드해요.

1. 저장소의 **Actions** 탭 → `Build 방치형 오토 APK` 워크플로 → 가장 최근 실행을 열어요.
2. 아래 **Artifacts** 에서 `idle-autoplayer-debug-apk` 를 내려받아 압축을 풀면 `app-debug.apk` 가 있어요.
3. 폰으로 옮겨 설치해요. (출처를 알 수 없는 앱 설치 허용이 필요해요.)

직접 빌드하려면 Android Studio 에서 `idle-autoplayer` 폴더를 열고 **Run** 하거나, 터미널에서:

```bash
cd idle-autoplayer
./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk
```

## 처음 설정

1. 앱을 열고 **접근성 설정 열기** → 설치된 앱(다운로드한 앱) → **방치형 오토** 를 켜요.
   - 안드로이드 13 이상에서 스위치가 회색이면: 설정 → 애플리케이션 → 방치형 오토 → 오른쪽 위 ⋮ → **제한된 설정 허용** 을 먼저 눌러요.
2. **＋ 새 매크로 만들기** 로 게임용 매크로를 하나 만들어요.
3. **▶ 패널 열기** 를 누르면 앱이 뒤로 가고 화면 위에 작은 패널이 떠요. 이제 게임을 실행해요.

## 패널 버튼

| 버튼 | 하는 일 |
|---|---|
| ⠿ | 패널 끌어서 옮기기 |
| ▶ / ■ | 재생 시작 / 정지 |
| ＋ | 화면 가운데에 번호 마커 추가 → 끌어서 게임 버튼 위에 놓기 |
| － | 마지막 동작 삭제 |
| ● / ■ | 녹화 시작 / 종료 (녹화 중엔 빨간 테두리가 보여요) |
| ✕ | 패널 닫기 |

- 마커를 **짧게 누르면** 그 동작의 좌표·간격이 패널 아래에 표시돼요.
- 마커·좌표는 옮기는 즉시 저장돼요. 간격·반복·자동 정지는 앱의 **편집** 화면에서 바꿔요.
- 패널 바로 아래 자리는 눌리지 않으니 패널은 빈 곳에 두세요.
- 화면 회전이나 해상도가 바뀌면 좌표가 어긋나요. 게임은 항상 같은 방향으로 켜 주세요.

## 자주 묻는 것

- **게임을 끄면?** 패널은 남아 있어요. 다른 앱에서도 터치가 들어가니 쓰지 않을 땐 ■ 로 멈추거나 ✕ 로 닫아 주세요.
- **배터리 절약 때문에 멈추는데요?** 설정 → 배터리 → 방치형 오토 → 제한 없음(최적화 제외)으로 두면 좋아요. 접근성 서비스는 보통 시스템이 끄지 않아요.
- **다른 폰에서도 같은 매크로?** 해상도가 같아야 해요. 다르면 패널을 열 때 경고가 떠요.

## 림버스 컴퍼니 향상된 자동전투 (개발 중)

`limbus/LimbusPlanner.kt` 에 합 배치 판단 로직이 들어 있어요. 화면 인식과 분리된 순수 로직이고 단위 테스트 22개(`app/src/test`)로 검증돼요.

**반영한 게임 규칙** (공략·위키 조사 기준, 패치로 달라질 수 있어요)
- 합 예측 5단계: 매우 우세(90~100%) / 우세(60~90%) / 보통(40~60%) / 열세(10~40%) / 매우 열세(0~10%). 표시 승률은 단순 계산이라 참고용이에요.
- 나를 노리는 적 스킬과는 속도와 상관없이 합을 할 수 있어요.
- 다른 수감자를 노리는 적 스킬은 내 속도가 그 적 스킬보다 빠를 때만 합을 뺏어올 수 있어요. 느리거나 같으면 일방 공격 판정이 되고 그 공격은 원래 대상이 그대로 맞아요. (같은 속도 처리는 자료마다 달라 옵션으로 두었어요.)
- 적 스킬 하나에 우리 스킬이 여럿 붙으면 마지막에 지정한 하나만 합을 하고 나머지는 일방 공격이 돼요. 그래서 계획에 **지정 순서**가 함께 나와요 (일방 공격 → 방어 → 합).
- 흐트러진 적은 행동하지 못하고 내성이 통째로 바뀌어 피해를 2배(흐트러짐+ 2.5배, ++ 3배) 받아요. 약한 스킬도 충분히 들어가는 곳이에요.
- 흐트러짐 선을 넘기면 그 적의 준비한 스킬이 전부 취소돼요. 강한 스킬의 가장 좋은 쓸 곳은 멀쩡한 적을 선 아래로 밀어 넣는 것이에요.
- 합에서 지는 코인은 파괴되고 그 코인의 효과도 사라져요. 강한 스킬을 불안한 합에 쓰면 손해라서 합은 약한 스킬로, 강한 스킬은 아껴요.
- 물리 내성: 내성 0.5배, 견딤 0.75배, 보통 1배, 취약 2배. 공격 유형을 알면 조합 선택에 반영해요.
- 아무도 막지 않은 적 공격은 그 대상이 일방적으로 맞아요. 그래서 막을 사람이 없으면 보통 합으로라도 받고(옵션), 그것도 안 되면 노려진 수감자가 방어 스킬(회피/가드)로 받아요(옵션).
- 기본 승률 오토의 약점(속도 빠른 수감자가 승률이 낮아도 합을 걸고, 한두 적에게 공격이 몰림)을 최대 가중치 매칭과 분산으로 피해요.

**판단 순서**
1. 매우 우세 → 우세 합을 전체 질이 최대가 되게 짝지어요. 적 스킬 하나에 합 하나. 같은 등급이면 **약한 스킬로 합**을 하고 강한 스킬은 아껴요 (옵션).
2. 아직 안 막힌 "우리를 노리는" 공격은 보통 합으로 막거나, 노려진 수감자가 방어 스킬로 받아요.
3. 남는 스킬은 일방 공격이에요 (`AttackAllocator`).
   - 처치할 수 있는 적이 있으면 **가장 약한 스킬(조합)** 로 끝내요. 넘치는 위력은 낭비예요.
   - 멀쩡한 적을 다음 흐트러짐 선 아래로 밀어 넣을 수 있으면 가장 싼 조합으로 밀어 넣어요. 넘기면 그 뒤 스킬은 2배로 들어가요.
   - 나머지는 **강한 스킬은 멀쩡한 적**(체력 낮은 순), **약한 스킬은 흐트러진 적**에게 써요. 체력 숫자를 몰라도 이 규칙은 동작해요.

**스킬 위력 추정** (`SkillPower`): 기대 위력 = 기본 위력 + 코인 위력 × 코인 수 × 앞면 확률. 앞면 확률은 50% + 정신력% (SP 45 → 95%). 숫자를 못 읽으면 스킬 3 > 2 > 1 등급으로 대신해요.

화면을 읽어 판을 만드는 부분(스크린샷 → 예측 글자·속도·타겟 인식)과 드래그로 배치를 적용하는 부분은 실제 전투 스크린샷으로 보정한 뒤 추가할 예정이에요.

## 구조

```
idle-autoplayer/
├─ app/src/main/
│  ├─ AndroidManifest.xml
│  ├─ java/com/pcylove/idleauto/
│  │  ├─ Model.kt             # Step / Script / ScriptStore (SharedPreferences + JSON)
│  │  ├─ Player.kt            # 동작을 순서대로 예약·반복 실행
│  │  ├─ AutoService.kt       # 접근성 서비스: dispatchGesture 로 실제 터치, 볼륨↓ 비상 정지
│  │  ├─ OverlayController.kt # 떠 있는 패널·마커·녹화 레이어 (TYPE_ACCESSIBILITY_OVERLAY)
│  │  ├─ MainActivity.kt      # 권한 안내 + 매크로 목록
│  │  ├─ EditorActivity.kt    # 이름·반복·간격 편집
│  │  ├─ Ui.kt                # 코드로 UI 를 그리는 도우미
│  │  ├─ limbus/LimbusPlanner.kt # 림버스 합 배치 판단 로직 (테스트: app/src/test)
│  │  └─ limbus/AttackAllocator.kt # 남는 스킬의 일방 공격 배분 (처치 → 흐트러뜨리기 → 강약 분배)
│  └─ res/                    # 문자열, 접근성 서비스 설정, 아이콘
└─ .github/workflows (저장소 루트) → build-idle-autoplayer.yml
```

최소 안드로이드 8.0 (API 26), 대상 API 35. 별도 권한 요청 창 없이 접근성 서비스 하나만 켜면 돼요 (오버레이는 접근성 오버레이 창을 써서 "다른 앱 위에 표시" 권한이 필요 없어요).
